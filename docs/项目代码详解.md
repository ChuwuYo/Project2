# 项目代码详解：FER2013 人脸表情识别

这份文档按做项目的顺序讲：**读取数据 → 预处理 → 搭建模型 → 训练 → 验证模型 → 测试评估**，再讲怎么调试、网页演示和验收时可能被问到的问题。建议边看边打开对应的源码文件。

---

## 1. 一句话概括

读取 FER2013 的 CSV（每行一张 48×48 灰度人脸 + 表情标签），用改造过的 ResNet18 从头训练 7 分类模型；只用 Training 训练、只用 PublicTest 做一切选择、PrivateTest 只做最终评估；最终把 6 个模型的预测概率取平均，PrivateTest 准确率 73.11%。

## 2. 整体流程（六步）

```
① 读取数据   dataset.py：解析 CSV → 缓存 data/fer2013.npz → 按 Usage 分成三个子集
             check_data.py：检查数量、标签、空白图、重复图
② 预处理     dataset.py：0–1 缩放 + 标准化；训练集另做数据增强
③ 搭建模型   model.py：改造 ResNet18（1 通道输入，输出 7 类）
④ 训练       train.py：只用 Training（28709 张）算 loss、反向传播、SGD 更新参数
⑤ 验证模型   train.py：每轮在 PublicTest（3589 张）上验证 → 保存最佳模型、调学习率、早停、决定 TTA
             evaluate.py --split PublicTest：比较单模型 / 集成，选出最终方案 → final_runs.txt
⑥ 测试评估   evaluate.py：最终方案在 PrivateTest（3589 张）上只评估一次 → 总准确率、每类准确率、混淆矩阵
```

另外：`app.py` 是网页演示，推理方式与 `evaluate.py` 完全相同；`tests/test_pipeline.py` 自动检查上面各步有没有写错。

## 4. 第一步：读取数据（`dataset.py`、`check_data.py`）

### 4.1 CSV 格式

三列：`emotion`（0–6）、`Usage`（Training / PublicTest / PrivateTest）、`pixels`（2304 个用空格隔开的 0–255 数字，即 48×48）。列的先后顺序不要求（`icml_face_data.csv` 是 emotion, Usage, pixels；Kaggle 的 `fer2013.csv` 是 emotion, pixels, Usage），代码按列名读取。

类别：0 愤怒、1 厌恶、2 恐惧、3 快乐、4 悲伤、5 惊讶、6 中性（`CLASSES`、`CLASSES_ZH`）。

### 4.2 读取与缓存

- `find_csv`：在 `data/` 里找 `icml_face_data.csv` 或 `fer2013.csv`。
- `_parse_csv`：逐行读取，按列名取值（三列顺序不同也能读），检查每行像素个数是否为 2304，转成 `uint8` 的 48×48 数组。
- `load_all`：第一次解析 CSV 后用 `np.savez_compressed` 存成 `data/fer2013.npz`，以后直接读缓存（约 1 秒）。
- `load_split(split)`：全项目唯一的取数入口，按 `Usage` 筛出某个子集，返回 `(images, labels)`。

### 4.3 三个子集怎么用

| 子集 | 数量 | 用途 | 谁会读取 |
|---|---|---|---|
| Training | 28709 | 训练：计算 loss、更新参数 | `train.py` |
| PublicTest | 3589 | 验证：选最佳轮次、调学习率、早停、决定 TTA、比较方案 | `train.py`、`evaluate.py --split PublicTest` |
| PrivateTest | 3589 | 测试：最终方案确定后只评估一次 | 只有 `evaluate.py` |

所有脚本都通过 `load_split("子集名")` 取数据，`train.py` 只请求 Training 和 PublicTest，测试会自动检查这一点。

### 4.4 数据检查（`check_data.py`）


检查三个子集数量（28709 / 3589 / 3589）、标签范围 0–6、尺寸 48×48、均值方差，统计空白图和跨子集重复图，画类别分布和样例图。结果在 `reports/data_check/report.md`。

发现：13 张几乎纯色的空白图；PublicTest 280 张、PrivateTest 288 张与 Training 像素完全相同。这是官方数据本身的问题，我们保持官方划分不改，并在 README 中如实说明。

各子集、各类别数量（来自 `reports/data_check/report.md`）：

## 5. 第二步：预处理（`dataset.py`）

### 5.1 标准化（所有数据都做）

```python
v2.ToDtype(torch.float32, scale=True)   # 0–255 → 0–1
v2.Normalize([MEAN], [STD])             # (x − 0.5077) / 0.2550
```

- `MEAN=0.5077`、`STD=0.2550` 只用 Training 的像素算出来。不用验证集和测试集统计，避免信息泄露。测试会重新计算并核对。
- 为什么要标准化：让输入大致在 0 附近、方差为 1，梯度更稳定，训练更快。

### 5.2 数据增强（只对训练集）

| 操作 | 作用 |
|---|---|
| `RandomHorizontalFlip` | 左右翻转，表情左右对称，等于数据量翻倍 |
| `RandomAffine(degrees=10, translate=0.1, scale=0.9–1.1)` | 小角度旋转、平移、缩放，模拟人脸位置和角度变化 |
| `RandomErasing(p=0.25)`（只 A3） | 随机遮挡一块，迫使模型不依赖局部 |

验证、测试、前端都不做增强，只做标准化（`build_transform(train=False)`）。

**为什么要增强**：训练集只有 2.9 万张，模型很快就会把训练图“背下来”。A0 不做增强，训练集准确率到 99.7%，验证集只有 58.87%（3 个种子平均），严重过拟合；A1 加了增强，验证集提高到 69.19%。增强让模型每轮看到的都是略有不同的图，学到的是表情本身，而不是某张图的像素。验证和测试不做增强，因为评估要看的是原图的真实表现。

### 5.3 `FERDataset` 与 DataLoader

- `FERDataset` 把 `(N,48,48)` 数组变成 `(N,1,48,48)` 张量，`__getitem__` 返回一张变换后的图和标签。
- `utils.make_loader`：训练集 `shuffle=True` 并用固定种子的生成器（可复现）；验证/测试集固定顺序。

### 5.4 前端用同一套预处理

网页演示里，检测到的人脸先裁成 48×48 灰度图，再交给 `preprocess_face`。它内部调用的就是 `build_transform(train=False)`，所以和验证、测试的预处理完全相同（测试里逐元素比较过）。

## 6. 第三步：搭建模型（`model.py`）

### 6.1 为什么改 ResNet18

标准 ResNet18 是给 224×224 彩色图设计的：第一层 7×7 卷积 stride 2，再接 maxpool，一开始就把图缩小 4 倍。48×48 的小图这样会损失太多细节。所以改三处：

1. `conv1`：输入通道 3→1（灰度），卷积核 7×7 stride 2 → 3×3 stride 1。
2. `maxpool`：去掉（换成 `nn.Identity()`）。
3. `fc`：`Dropout + Linear(512, 7)`，输出 7 类。

### 6.2 每一层的作用和输出尺寸

| 层 | 作用 | 输出尺寸（通道×高×宽） |
|---|---|---|
| 输入 | 一张标准化后的 48×48 灰度人脸 | 1×48×48 |
| conv1（3×3 卷积）+ BN + ReLU | 提取边缘、明暗变化等最基础的特征；BN 稳定训练，ReLU 引入非线性 | 64×48×48 |
| layer1（2 个残差块） | 组合出眼角、嘴角等局部纹理，尺寸不变 | 64×48×48 |
| layer2（2 个残差块，第一个步长 2） | 尺寸减半、通道加倍，看到更大范围（眼睛、嘴巴整体形状） | 128×24×24 |
| layer3（同上） | 继续减半，组合成五官之间的关系 | 256×12×12 |
| layer4（同上） | 最高层特征，接近“在笑”“皱眉”这类表情含义 | 512×6×6 |
| 全局平均池化 | 每个通道的 6×6 取平均，变成一个 512 维向量，与位置无关 | 512 |
| Dropout + 全连接（Linear 512→7） | Dropout 随机丢弃一部分特征防过拟合（只在 A3 中启用，比例 0.4）；全连接输出 7 类分数 | 7（logits，经过 softmax 变成概率） |

约 1100 万参数，从头训练，不用预训练权重。

### 6.3 残差块是什么

每个残差块：`输出 = ReLU(F(x) + x)`，其中 F 是两层 3×3 卷积 + BN。“+ x”这条捷径让梯度能直接往前传，网络更深也容易训练。尺寸变化时捷径用 1×1 卷积对齐通道和尺寸。

## 7. 第四步：训练（`train.py`）

### 7.1 消融实验 `EXPERIMENTS`

| 名称 | 增强 | 标签平滑 | Dropout | RandomErasing |
|---|---|---|---|---|
| A0 | 否 | 0 | 0 | 否 |
| A1 | 是 | 0 | 0 | 否 |
| A2 | 是 | 0.1 | 0 | 否 |
| A3 | 是 | 0.1 | 0.4 | 是 |

每组只比上一组多一个改动，这样才能说清楚是哪个改动带来的变化。

### 7.2 损失函数：交叉熵（+ 标签平滑）

- `nn.CrossEntropyLoss` = softmax + 负对数似然，衡量预测概率和真实类别的差距。
- 计算方法：模型先输出 7 个分数（logits），softmax 把它们变成加起来等于 1 的概率，loss = −log(正确类别的概率)。正确类概率 0.9 时 loss ≈ 0.105；只有 0.1 时 loss ≈ 2.30。所以模型越确信正确答案，loss 越小；一开始乱猜（每类约 1/7）时 loss ≈ 1.95。
- 一个 batch 的 loss 是 128 张图 loss 的平均；训练的目标就是让它变小（7.3）。
- 标签平滑 0.1：把真实标签从 `[0,0,1,0,...]` 改成“正确类 0.9 + 其余平分 0.1”，防止模型过度自信。FER2013 标签本身有噪声，这样做理论上有帮助；我们的实验里 A2 和 A1 差别不大。

### 7.3 参数是怎么更新的（`train_one_epoch`）

训练集 28709 张，每次取 128 张（一个 batch），一轮约 225 次更新。每个 batch 做这几步：

```python
logits = model(x)                    # 1. 前向：算出 7 类的分数
loss = criterion(logits, y)          # 2. 算 loss：预测和真实标签差多少
optimizer.zero_grad(set_to_none=True)  # 3. 清空上一次的梯度（PyTorch 默认会累加）
scaler.scale(loss).backward()        # 4. 反向传播：算出 loss 对每个参数的梯度
scaler.step(optimizer)               # 5. 更新参数：沿着让 loss 变小的方向走一小步
scaler.update()                      #    （混合精度用，见 7.5）
```

第 5 步用的是 SGD（随机梯度下降），设置为 `SGD(lr=0.01, momentum=0.9, nesterov=True, weight_decay=5e-4)`：

- **基本公式**：新参数 = 旧参数 − 学习率 × 梯度。梯度指向 loss 增大的方向，减去它 loss 就会变小。学习率 0.01 决定每一步走多远。
- **动量 momentum 0.9**：不只看这一次的梯度，还保留之前更新方向的 90%，像小球滚下坡有惯性。这样更新方向更稳定，不容易被某一个 batch 带偏。
- **Nesterov**：动量的改进版，先按惯性“往前看一步”再算梯度，通常收敛更稳。
- **weight decay 5e-4**：每次更新时让参数稍微往 0 收缩一点（等价于 L2 正则），防止参数过大、过拟合。
- **学习率会变**：每轮验证后，如果 PublicTest 准确率连续 5 轮没有提高，`ReduceLROnPlateau` 把学习率减半（0.01 → 0.005 → …），让模型后期细调。具体见第 8 章。

训练时 `model.train()` 打开 Dropout 和 BN 的训练模式；只有训练这一步会改参数，验证和测试都不会。

### 7.4 每一轮做什么（`main` 中的循环）

1. `train_one_epoch`：在 Training 上把所有 batch 跑一遍（7.3），得到训练 loss 和准确率。
2. `validate`：在 PublicTest 上验证（第 8 章）。
3. 根据验证准确率调整学习率，把这一轮的结果追加写入 `log.csv`。
4. 验证准确率创新高就保存 `best.pt`；每轮都保存 `last.pt`（含优化器等完整状态，用于 `--resume` 断点续训）。
5. 连续 20 轮验证准确率没提高就提前停止（早停），否则最多 100 轮。

### 7.5 混合精度（AMP）

GPU 上用 `torch.autocast` + `GradScaler`：部分计算用 float16，速度更快、显存更少；`GradScaler` 放大 loss 防止小梯度下溢。CPU 上自动关闭。

### 7.6 终端打印的日志怎么看

开始训练时打印设备、实验配置和数据量：

```

Training 28709 张 | PublicTest 3589 张
```

之后每轮打印一行。下面是最终模型 A1_s2 第 77 轮（它的最佳轮）的真实记录：

```

```

| 部分 | 意思 |
|---|---|
| `[ 77]` | 第 77 轮 |
| `train 0.1907/0.9323` | 训练集 loss 0.1907 / 准确率 93.23%（在增强后的图上算） |
| `val 1.3906/0.6971` | PublicTest loss 1.3906 / 准确率 69.71% |

| `27s` | 这一轮用时（Colab T4） |

训练结束打印 `完成: {...}`，内容和 `summary.json` 一样，例如 A1_s2：最佳轮 77，PublicTest 准确率 0.6971，翻转 TTA 后 0.7030，`use_tta: true`。

同样的数字每轮都写进 `log.csv`（列：`epoch, train_loss, train_acc, val_loss, val_acc, lr, seconds`），训练完画成 `curves.png`。训练集准确率远高于验证集（93% 对 70%）说明仍有过拟合，所以靠验证集挑最佳轮、用早停。

### 7.7 输出文件（`runs/<实验>_s<种子>/`）

`config.json`（全部参数）、`log.csv`（每轮 loss/acc/lr/耗时）、`curves.png`（曲线）、`best.pt`、`last.pt`、`summary.json`。

压缩包里的 `runs/` 只给最终 6 个模型保留了 `best.pt`（`last.pt` 太大没放），其余 6 个只有日志和曲线。

**防止覆盖**：`main` 一开始会检查输出目录。如果里面已经有 `best.pt`，又没有“`--resume` + `last.pt`”可以续训，就直接报错退出。所以误敲 `python train.py --exp A1 --seed 0` 不会毁掉 `runs/A1_s0` 这个最终模型。自己训练时请加 `--out runs_local`，结果放在 `runs_local/` 里。

## 8. 第五步：验证模型（PublicTest）

### 8.1 每轮验证（`validate`）

- `model.eval()`：关掉 Dropout，BN 用训练时统计好的均值方差；`torch.inference_mode()`：不算梯度，所以**不会改任何参数**。
- 数据只做标准化，不做增强，计算 PublicTest 的 loss 和准确率。

### 8.2 验证结果用来做什么

| 用途 | 规则 |
|---|---|
| 选最佳模型 | 验证准确率最高的那一轮存为 `best.pt`，最后用的就是它，不是最后一轮 |
| 调学习率 | 连续 5 轮不提高，学习率减半 |
| 早停 | 连续 20 轮不提高，停止训练 |
| 看过拟合 | 训练准确率一直涨、验证准确率不涨甚至下降，就是过拟合（A0 最明显） |

### 8.3 是否用翻转 TTA

训练结束后，用 `best.pt` 在 PublicTest 上分别算“不翻转”和“原图 + 翻转取平均”的准确率，后者更高就在 `summary.json` 里记 `use_tta: true`。评估和前端都读这个决定，所以这个选择也只依赖 PublicTest。

### 8.4 选最终方案（只用 PublicTest）


1. 阶段 1：A0–A3 各跑 1 个种子，PublicTest 前两名是 A1、A2。（之后 A0、A3 也补到 3 个种子，只为让消融结论更可靠，不改变最终方案。）
2. 阶段 2：A1、A2 各补种子 1、2，得到 6 个模型。
3. 阶段 3：用 `evaluate.py --split PublicTest` 比较：最佳单模型 70.30%、A1×3 71.50%、A2×3 70.63%、A1+A2×6 71.52%，选最高的六模型集成，写入 `final_runs.txt`。
4. 阶段 4：只在这之后跑一次 PrivateTest：73.11%。

为什么集成更好：不同种子的模型犯的错误不完全一样，平均后随机误差相互抵消。

### 9.2 评估结果（PrivateTest，3589 张）

**总准确率 73.11%**。每一类的结果：

| 类别 | 准确率（召回率） | 精确率 | F1 | 图片数 |
|---|---|---|---|---|
| 0 愤怒 | 65.8% | 67.0% | 0.664 | 491 |
| 1 厌恶 | 70.9% | 84.8% | 0.772 | 55 |
| 2 恐惧 | 50.6% | 65.3% | 0.570 | 528 |
| 3 快乐 | 91.5% | 89.7% | 0.906 | 879 |
| 4 悲伤 | 62.1% | 57.9% | 0.600 | 594 |
| 5 惊讶 | 83.9% | 84.3% | 0.841 | 416 |
| 6 中性 | 75.6% | 67.1% | 0.711 | 626 |
| 平均（7 类等权） | 71.5% | 73.7% | 0.723 | 3589 |

“每一类的准确率”= 这一类图片里被认对的比例，就是召回率。

### 9.3 评价方式：指标怎么理解

- 准确率 = 预测正确的数量 / 总数。
- Precision（精确率）：预测为某类的样本里，有多少真是这一类。
- Recall（召回率）：真实为某类的样本里，有多少被找出来。
- F1：precision 和 recall 的调和平均。
- 混淆矩阵：第 i 行第 j 列 = 真实是 i 类、被预测成 j 类的比例。我们的结果里快乐（F1 0.91）和惊讶（0.84）最好，恐惧（召回 0.51）最差，常被认成悲伤。
- 为什么不只看总准确率：类别不均衡，快乐占 24%，厌恶只有 1.5%。模型就算完全认不出厌恶，总准确率也只掉一点点，所以还要看每一类的召回率、精确率和 7 类等权平均（macro avg）。
- 评价的规则：所有指标只在 PrivateTest 上算一次，模型和方案在这之前已经用 PublicTest 定好，测试结果不再用来改任何东西。

## 11. 网页演示：`app.py`


### 上传 / 拍照

1. `detect_faces`：用 OpenCV 自带的 YuNet 深度学习检测器找人脸，返回人脸框和双眼位置。
2. `align_crop`：按双眼连线把脸转正，以人脸中心截取 1.2 倍框大小的正方形，缩放到 48×48 灰度图（接近 FER2013 的裁剪方式）。
3. `preprocess_face` + `model_probs`：与评估完全相同的预处理和推理（6 模型集成 + TTA）。
4. 显示 7 类概率和“模型看到的 48×48 人脸”。

### 实时摄像头

左边是摄像头，右边按类别 0–6 固定顺序显示最大那张脸的 7 类概率。每 0.1 秒浏览器发一帧给服务器（`cam.stream`）：

1. `detect_live`：缩小到 320 宽检测人脸 → 所有人脸一次成批推理；
2. 服务器只返回人脸框坐标（归一化到 0–1）和文字，几百字节，而不是整张图片；
3. `DRAW_JS`：浏览器在摄像头画面上叠一层 canvas，直接画框和表情；1 秒没有新结果（停止录制）就清空。

为什么这样做：如果把画好框的整张图回传，要么需要右边再放一个图片框（双倍渲染），要么让摄像头组件同时作输入和输出——后者在 Gradio 6 里会让“录制/停止”按钮来回闪（已在无头浏览器中复现）。只回传坐标、浏览器端画框，是实时检测类网页的常见做法，传输量最小。

页头的准确率直接读取 `reports/` 中 `evaluate.py` 生成的结果，前端不做任何评估。只有报告里的模型和当前加载的模型完全相同时才显示这个数字；用 `--runs` 换成自己训练的模型时，页头会写“这组模型没有 PrivateTest 结果”，不会把 73.11% 挂到别的模型上。

### 界面样式

`THEME` 是在 Gradio 内置 `Base` 主题上改的配色（暖米白底、陶土橙强调色，亮色/暗色模式分别配色），`CSS` 只管页头、概率条和画框层的样式。`prob_html` 把 7 类概率按 0–6 固定顺序生成 HTML，最高的一类用强调色。样式只影响外观，与识别结果无关。

## 13. 实验记录：做过哪些尝试、提升了多少

所有数字都是 **PublicTest** 准确率（PrivateTest 只在最后用一次），每个实验跑 3 个随机种子，报告均值 ± 标准差。

### 13.1 消融实验：每次只加一个改动

| 实验 | 改动 | PublicTest | 比上一组 | 加翻转 TTA | 结论 |
|---|---|---|---|---|---|
| A0 | 基线：无数据增强 | 58.87% ± 0.61 | — | 59.35% ± 0.78 | 训练集 99.7%，严重过拟合 |
| A1 | + 翻转、旋转、平移、缩放 | 69.19% ± 0.52 | **+10.32** | 70.08% ± 0.23 | 提升最大，远超种子波动，增强有效 |
| A2 | + 标签平滑 0.1 | 69.26% ± 0.46 | +0.07 | 69.50% ± 0.81 | 差距在种子波动内，不能说更好 |
| A3 | + Dropout 0.4 + RandomErasing | 68.83% ± 0.31 | −0.43 | 69.56% ± 0.21 | 没有稳定提升 |

（“比上一组”单位是百分点。标准差约 0.3–0.6，只有超过这个范围的差距才算真的有区别。）

### 13.2 推理阶段的改进（不重新训练）

| 做法 | PublicTest | 比最佳单模型 |
|---|---|---|
| 最佳单模型 A1_s2（含翻转 TTA） | 70.30% | — |
| A2 三个种子集成 | 70.63% | +0.33 |
| A1 三个种子集成 | 71.50% | +1.20 |
| **A1 + A2 六模型集成（最终方案）** | **71.52%** | **+1.22** |

翻转 TTA 在 12 个模型中的 10 个上提高了 PublicTest 准确率，是否使用由每个模型各自决定。最终方案在 PrivateTest 上只评估一次：**73.11%**。

### 13.3 对照老师给的提高方向

| 方向 | 我们做了什么 | 结果 |
|---|---|---|
| 模型结构（BatchNorm、加深、ResNet 风格） | 用带 BatchNorm 的 ResNet18，针对 48×48 改了首层和 maxpool | 没有和其他网络对比（未做） |
| 超参数（学习率、batch size、轮数、scheduler） | lr 0.01、batch 128 固定；用 ReduceLROnPlateau 降学习率、早停决定轮数 | 没有系统搜索学习率和 batch size（未做） |
| 数据增强（对比有无增强） | A0 无增强 vs A1 有增强 | +10.32 个百分点，最有效 |
| 防止过拟合（Dropout、weight decay） | 所有实验都用 weight decay 5e-4；A3 加 Dropout 0.4 + RandomErasing | Dropout 没有稳定提升 |
| 类别不平衡（加权 loss、过采样） | 没做；厌恶只有 436 张 | 可以作为下一步 |
| 结果分析（训练曲线、易混淆类别） | 每个模型有 `curves.png`；混淆矩阵显示恐惧最常被认成悲伤（100 张）和愤怒（66 张） | 见第 9 章 |

讲法要点：结论必须有多次实验支撑；单次的小差距不足以说明方法更好。所以我们说“数据增强有效”，但不说“标签平滑有效”。


## 14. 验收问答（按老师要求的各项，对应我们的代码）

顺序按老师幻灯片“项目至少要包含这些部分”，最后对照“提高准确率的方向”。每题先说“**答**”；助教追问再说“**追问**”。“**代码**”是文件和行号，VS Code 按 Ctrl+G 输入行号跳转。没做过的就说没做过。

### 14.0 一段话介绍项目（30 秒）

> 我们做的是 7 类表情识别。用 ResNet18 从头训练，输入是 48×48 的灰度人脸。训练集做了数据增强，这一步让验证准确率从 59% 提高到 69%。所有选择都只看 PublicTest，最后把 6 个模型的预测概率取平均，在 PrivateTest 上只测了一次，准确率 73.11%。

### 14.1 数据读取与检查

**问：数据怎么读进来的？**
答：按列名读 CSV 的 emotion、Usage、pixels 三列，每行 2304 个像素还原成 48×48，再按 Usage 分成 Training 28709、PublicTest 3589、PrivateTest 3589 张。第一次解析后存成 npz 缓存，之后加载只要 1 秒左右。
代码：`dataset.py` 第 36–58 行 `_parse_csv()`，第 83 行 `load_split()`。

**问：做了哪些检查？**
答：`check_data.py` 检查三个子集的数量、标签范围 0–6、图片尺寸和各类别数量，还统计了空白图和跨子集的重复图。发现 13 张空白图，PublicTest 有 280 张、PrivateTest 有 288 张和训练集像素完全相同；官方划分没有改，只写进报告。
代码：`check_data.py` 第 34 行起；结果在 `reports/data_check/`。

**问：各类别数量怎么样？**
答：很不均衡。训练集快乐最多，7215 张；厌恶最少，只有 436 张，差了约 16 倍。所以评估时除了总准确率，还看每一类的结果。

### 14.2 预处理

**问：归一化怎么做的？**
答：像素先从 0–255 缩到 0–1，再减均值 0.5077、除以标准差 0.2550。这两个数只用训练集算，不碰测试数据。这样输入大致以 0 为中心，训练更稳定。
代码：`dataset.py` 第 32–33 行，第 97 行。

**问：数据增强做了哪些？为什么？**
答：只对训练集做：随机左右翻转，±10° 旋转，±10% 平移，0.9–1.1 倍缩放。这些模拟的是拍照时头歪、位置偏、远近不同，表情类别不会变。模型每轮看到的图都不一样，就不容易死记训练图，验证准确率从 58.87% 提高到 69.19%。
追问（为什么不上下翻转）：真实场景里没有倒过来的脸。
代码：`dataset.py` 第 100–104 行；`utils.py` 第 53 行决定只有训练集增强。

**问：验证、测试和网页的预处理一样吗？**
答：一样，都调用同一个 `build_transform(train=False)`，自动测试里也检查了这一点。

### 14.3 模型：每一层的作用和输出尺寸

**问：用的什么模型？**
答：ResNet18，一个 CNN 分类模型，没用预训练，从头训练。针对 48×48 灰度图改了三处：输入 1 通道；第一层卷积改成 3×3、步长 1，并去掉 maxpool；最后输出 7 类。
代码：`model.py` 第 14–17 行。

**问：每一层的作用和输出尺寸？**

| 层 | 输出尺寸 | 作用 |
|---|---|---|
| 输入 | 1×48×48 | 归一化后的灰度人脸 |
| conv1 + BN + ReLU | 64×48×48 | 提取边缘、明暗等基础特征 |
| layer1（2 个残差块） | 64×48×48 | 组合成眼角、嘴角等局部纹理 |
| layer2 | 128×24×24 | 尺寸减半、通道加倍，看到眼睛、嘴巴的整体形状 |
| layer3 | 256×12×12 | 五官之间的关系 |
| layer4 | 512×6×6 | 接近“笑”“皱眉”这类表情含义 |
| 全局平均池化 | 512 | 每个通道取平均，变成一个向量 |
| 全连接 | 7 | 输出 7 类分数，softmax 后变成概率 |

追问（尺寸怎么变小的）：layer2–4 的第一个卷积步长是 2，所以每次长宽减半。

**问：为什么用 ResNet？**
答：残差块的输出是“卷积结果 + 输入本身”，梯度可以通过这条捷径直接传回前面的层，网络深了也好训练。每个卷积后都有 BatchNorm，把数值调到稳定的范围，训练更稳，也能用较大的学习率。
追问：我们没有和 VGG 等其他结构做对比。

**问：为什么去掉 maxpool、第一层改 3×3？**
答：原版 ResNet 是给 224×224 的图设计的，一开始就缩小 4 倍。48×48 缩完只剩 12×12，细节丢太多；改完之后最后一层还有 6×6。
代码：`model.py` 第 15–16 行。

**问：为什么不用预训练模型？**
答：常见的预训练模型是在 224×224 彩色照片上训练的，和 48×48 灰度人脸差别很大；从头训练也能到 70% 左右，结构改动更好解释。

**问：用了 Dropout 吗？**
答：代码里有，A3 实验开了 0.4，但没有稳定提升。最终用的 A1、A2 没开 Dropout。
代码：`model.py` 第 17 行，`train.py` 第 37–40 行。

### 14.4 训练：损失函数和参数更新

**问：损失函数用的哪个？为什么？**
答：交叉熵，loss = −log(模型给正确类别的概率)。正确类概率越低，罚得越重，这是多分类的标准做法；它和 softmax 搭配，梯度形式简单，训练稳定。
追问（标签平滑）：A2 把正确类的目标从 1 改成 0.9，防止模型过度自信；结果只比 A1 高 0.07 个百分点，在随机波动内，不能说有用。
代码：`train.py` 第 123 行，第 66–68 行算每个 batch 的 loss。

**问：参数是怎么更新的？**
答：每次取 128 张图，前向算出 loss，清掉上一步的梯度，反向传播算出每个参数的梯度，再由优化器更新参数。整个训练集过一遍是一轮。
代码：`train.py` 第 71–74 行。

**问：优化器和超参数？**
答：SGD，动量 0.9（Nesterov），学习率 0.01，weight decay 5e-4，batch size 128，最多 100 轮。动量会沿着之前的方向继续走，减少来回震荡；weight decay 每步把权重往 0 拉一点，防止过拟合。
追问：没有和 Adam 对比，也没有系统搜索学习率和 batch size。
代码：`train.py` 第 48–52 行（默认值），第 124–125 行。

**问：学习率怎么调整？**
答：用 ReduceLROnPlateau：PublicTest 准确率连续 5 轮不提高，学习率减半。最终模型 A1_s2 到第 77 轮时已经从 0.01 降到 0.00125。
代码：`train.py` 第 126–127 行，第 152 行。

**问：什么时候停止训练？**
答：PublicTest 准确率连续 20 轮不提高就停（早停），保存的是准确率最高那一轮的 `best.pt`。
代码：`train.py` 第 145–147 行，第 157–162 行。

**问：混合精度是什么？**
答：GPU 上部分计算用 16 位浮点，更快、更省显存；GradScaler 防止梯度太小变成 0。不影响准确率，T4 上一轮约 27 秒。
代码：`train.py` 第 66 行，第 128 行。

### 14.5 训练记录

**问：每轮记录了什么？**
答：每轮的训练 loss 和准确率、验证 loss 和准确率、学习率、用时，写进 `log.csv`，同时打印在终端；训练结束画成 `curves.png`。
代码：`train.py` 第 154–156 行，第 178 行；`utils.py` 第 134 行 `plot_curves()`。

**问：曲线说明了什么？**
答：不加增强的 A0 训练准确率到 99.7%，验证只有 58.9%，明显过拟合；加增强后差距缩小。最终模型 A1_s2 第 77 轮训练 93.2%、验证 69.7%，验证 loss 后期在上升，但准确率还在涨，所以我们按验证准确率选最佳轮。

### 14.6 验证选模型

**问：验证集用来做什么？**
答：PublicTest 决定所有选择：保存哪一轮、学习率什么时候减半、什么时候停、要不要用 TTA、最终用哪几个模型。PrivateTest 只在 `evaluate.py` 里读，自动测试检查训练从不读它。
代码：`train.py` 第 111 行只读 PublicTest。

**问：TTA 是什么？**
答：测试时把原图和左右翻转图都预测一次，概率取平均。每个模型训练完在 PublicTest 上比较，有提高才开，12 个模型里 10 个开了。
代码：`utils.py` 第 79–83 行；`train.py` 第 168–176 行。

**问：最终方案怎么选的？集成为什么有用？**
答：在 PublicTest 上比较，A1、A2 各 3 个种子共 6 个模型取概率平均，71.52%，最佳单模型是 70.30%。不同种子的模型犯的错不完全相同，平均之后更稳。
代码：`evaluate.py` 第 70 行；模型列表在 `final_runs.txt`。

### 14.7 测试评估

**问：怎么评估的？结果多少？**
答：`evaluate.py` 在 PrivateTest 3589 张上，用 6 个模型的平均概率取最大的一类，算总准确率、每类的精确率、召回率、F1 和混淆矩阵。只跑了一次，准确率 73.11%。
代码：`evaluate.py` 第 63–69 行预测，第 81–89 行生成报告。

**问：各类别准确率？**
答：快乐 91.5%，惊讶 83.9%，中性 75.6%，厌恶 70.9%，愤怒 65.8%，悲伤 62.1%，恐惧 50.6%。

**问：哪类最难？为什么？**
答：恐惧，最常被认成悲伤（100 张）和愤怒（66 张），这几种表情本来就像。厌恶训练图只有 436 张，样本少。

**问：为什么 PrivateTest（73.11%）比 PublicTest（71.52%）高？**
答：两个子集的图片不同，有随机差异。我们没有在 PrivateTest 上做任何选择，所以这是一次性的真实结果。

### 14.8 代码与复现

**问：代码结构？**
答：（目录说明见第 3 章。）七个文件各管一件事：`dataset.py` 读数据和预处理，`model.py` 模型，`train.py` 训练，`evaluate.py` 测试评估，`utils.py` 共用函数，`check_data.py` 数据检查，`app.py` 网页演示；`tests/` 里有 9 项自动测试。

**问：别人怎么复现？**
答：复现准确率：运行 `python evaluate.py`，用交付的 6 个模型得到 73.11%；加 `--single` 是最佳单模型 A1_s2，71.11%。重新训练：`python train.py --exp A1 --seed 0 --out runs_local`。随机种子固定，每个模型的配置存在 `config.json`；GPU 计算有少量随机性，重训会有约 ±0.5% 的差别。
代码：`utils.py` 第 24 行 `set_seed()`。

**问：参考了什么？**
答：参考了 LetheSec 的 FER2013 项目的思路（首层 3×3、去 maxpool、增强、标签平滑、TTA），代码是自己写的；它用 PrivateTest 选模型，我们改成只用 PublicTest。来源写在 README 和 `references/references.yaml`。

### 14.9 实验记录与提高方向

**问：做过哪些尝试？结果如何？**
答：每次只加一个改动，各跑 3 个种子：A0 无增强 58.87%；A1 加增强 69.19%（+10.32）；A2 再加标签平滑 69.26%（+0.07）；A3 再加 Dropout 和随机擦除 68.83%（−0.43）。只有增强的提升超出了种子之间的波动。之后用 TTA 和 6 模型集成，PublicTest 到 71.52%。详见第 13 章。

**问：老师说的提高方向，哪些没做？**
答：类别加权的损失或过采样、和其他网络结构对比、系统搜索学习率和 batch size，这三项没做。

**问：为什么用多个模型平均，不用一个？**
答：同样的配置换种子，错的图片不完全一样，平均后更稳：PublicTest 上最佳单模型 70.30%，6 个平均 71.52%，所以按 PublicTest 选了平均。单模型也能现场跑（脚本输 2），PrivateTest 71.11%。

**问：如果继续改，先做什么？**
答：先处理类别不平衡，比如给厌恶、恐惧更高的损失权重，因为它们是最弱的类别。这只是计划，还没有实验结果。

### 14.10 其他

**问：网页上识别普通照片，为什么也要缩成 48×48 灰度？**
答：模型只在 48×48 灰度图上训练过，输入必须和训练时一样，否则准确率会下降。

**问：摄像头为什么有时认不准？**
答：训练数据是 FER2013 的低分辨率灰度图，和真实摄像头的光照、角度、人群都不一样；73.11% 只代表在这个测试集上的表现。
