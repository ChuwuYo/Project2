# 训练过程说明

这份文档如实记录本项目的模型是**在哪里、用什么工具、按什么步骤**训练出来的，以及你自己想复现时该怎么做。代码细节见 `项目代码详解.md`，实验结果见 `README.md` 和 `reports/model_selection.md`。

---

## 1. 总体情况

| 项目 | 内容 |
|---|---|
| 操作者 | 训练、监控、评估的命令由 AI 助手 Hark 在它自己的云端 Linux 沙盒里执行；你提供 Google 账号授权、确认每一步方案 |
| 写代码、预检 | Hark 沙盒（只有 CPU，很慢：1024 张图一轮要 168 秒） |
| 正式训练 | Google Colab，T4 GPU（16 GB），每轮约 26 秒，GPU 利用率约 97% |
| 控制 Colab 的方式 | Google 官方命令行工具 `google-colab-cli`，没有打开 Colab 网页笔记本 |
| 训练时间 | 2026-10-29 晚 ～ 2026-10-30 下午，共 12 个模型 |
| 纯训练时长 | 12 个模型合计约 6.7 小时（每个 15–45 分钟，见第 6 节） |
| 算力消耗 | Colab Pay As You Go 余额从 30.75 用到 21.45 计算单元（T4 约 1.07 单元/小时，含中途 VM 丢失浪费的部分） |
| 评估 PrivateTest | 只在最终方案确定后跑过 1 次，结果 73.11% |

整个流程：

```
写代码 → 数据审计 → 测试与预检（沙盒 CPU + Colab GPU）
→ 阶段 1：A0–A3 各 1 个种子（Colab）
→ 阶段 2：PublicTest 前两名 A1、A2 各补 2 个种子
→ 阶段 3：在 PublicTest 上比较单模型与集成，确定六模型集成
→ 阶段 4：PrivateTest 评估 1 次
→ 阶段 5：关闭 Colab，下载结果，写报告
→ 阶段 7（补充）：A0、A3 也补到 3 个种子，只为让消融结论更可靠
```

## 2. 训练前的准备

### 2.1 数据

1. 把 `icml_face_data.csv` 放进 `data/`。
2. 第一次调用 `dataset.load_split()` 时解析 CSV，存成 `data/fer2013.npz`（约 30 MB，之后读取只要不到 1 秒）。上传到 Colab 的也是这个 npz，而不是 CSV。
3. `python check_data.py` 做数据审计：三个子集数量 28709 / 3589 / 3589、标签 0–6、尺寸 48×48、13 张空白图、跨子集重复图。结果在 `reports/data_check/`，全部通过。官方划分不改。

### 2.2 训练前检查（任何一项不通过就不上 GPU）

| 检查 | 方法 | 结果 |
|---|---|---|
| 单元测试 | `pytest tests/`（7 项），沙盒和 Colab 各跑一次 | 全部通过 |
| 预处理一致 | 训练、评估、前端都调用同一个函数，测试里比较输出 | 误差 2e-7 |
| 不偷看 PrivateTest | 测试检查训练过程从不读取 PrivateTest | 通过 |
| 冒烟测试 | `python train.py --exp A2 --subset 2000 --epochs 2`，端到端跑通 | 通过 |
| 过拟合测试 | GPU 上用 512 张图反复训练，训练准确率达到 1.0，证明模型和损失函数没写错 | 通过 |
| 全量预检 | 全部数据跑 2 轮，看 loss 正常下降、每轮时间 | 正常，约 26 秒/轮 |

### 2.3 训练配置（所有实验相同）

SGD（momentum 0.9，Nesterov），lr 0.01，weight decay 5e-4，batch 128，最多 100 轮；ReduceLROnPlateau 按 PublicTest 准确率，5 轮不升 lr 减半；20 轮不升早停；GPU 上 fp16 混合精度。每个实验的完整参数保存在 `runs/<实验>_s<种子>/config.json`。

## 3. 用 Colab 训练的具体做法

### 3.1 为什么用命令行而不是 Colab 网页

Hark 只能在自己的沙盒里运行命令，不能替你一直开着浏览器标签页。Google 官方的 `google-colab-cli` 可以在命令行里分配 GPU、上传文件、执行代码、下载结果，适合这种情况。

### 3.2 登录和分配 GPU

```bash
pip install google-colab-cli
# 第一次需要 OAuth 授权：生成授权链接，你在浏览器里登录 Google 并同意，再把页面上的授权码发回
colab --auth oauth2 whoami        # 确认登录的账号
colab --auth oauth2 usage         # 查看余额和正在使用的 VM 数量
colab --auth oauth2 new -s fer --gpu T4     # 分配一台 T4 VM，会话名 fer
```

授权得到的令牌只保存在 Hark 的项目目录里，不在交付的代码包中。

### 3.3 上传代码和数据

```bash
tar czf fer_code.tgz dataset.py model.py utils.py train.py evaluate.py check_data.py tests requirements.txt final_runs.txt
colab --auth oauth2 upload -s fer fer_code.tgz /content/fer_code.tgz
colab --auth oauth2 upload -s fer data/fer2013.npz /content/fer2013.npz
```

然后在 VM 上解压到 `/content/fer`，数据放到 `/content/fer/data/`。Colab 自带 PyTorch 和 CUDA，只需补装缺的包。

### 3.4 后台跑训练队列

`colab exec` 一次最多约 100 秒，所以训练放在 VM 后台跑，用一个队列脚本依次训练。阶段 1 的脚本：

```bash
#!/bin/bash
cd /content/fer
for e in A0 A1 A2 A3; do
  python train.py --exp $e --seed 0 --resume > runs_$e.log 2>&1
done
touch /content/fer/QUEUE_DONE
```

启动方式：`setsid nohup bash /content/queue.sh > /content/queue.out 2>&1 < /dev/null &`。阶段 2、阶段 7 的脚本结构相同，只是实验和种子不同，并且已经有 `summary.json`（已完成）的实验会跳过。

### 3.5 查看进度

不需要登录 VM 的终端，只要下载日志看：

```bash
colab --auth oauth2 download -s fer /content/fer/runs_A1.log ./runs_A1.log
colab --auth oauth2 ls -s fer /content/fer/runs/A1_s0     # 出现 summary.json 就表示这个实验训练完了
```

`train.py` 每轮把 `epoch, train_loss, train_acc, val_loss, val_acc, lr, seconds` 追加到 `log.csv`，并保存 `last.pt`（可续训）；PublicTest 准确率创新高时保存 `best.pt`。

### 3.6 遇到的问题：VM 被反复回收

10-29 晚上，没有打开网页的 Colab VM 在 13–30 分钟内就被回收了 5 次，训练全部丢失。试过的办法：

| 办法 | 效果 |
|---|---|
| 定时调用 keep-alive 接口 | 无效 |
| 用一个长时间的 exec 让 kernel 一直忙 | 无效 |
| 用 Hark 的浏览器登录 Google 打开 Colab 网页 | 被 Google 安全拦截 |
| **在 VM 上装 colab-cli，每 50 秒连回自己的 kernel 执行一次 `sleep(45)`**（`hb.sh`） | **有效**，之后直到训练结束都没有再被回收 |

依据：Colab 按“kernel 有活动 + 有活跃连接”判断 VM 是否在用；命令行工具每次执行完就断开，所以 VM 被当成闲置。

同时加了第二道保险——**频繁备份 + 断点续训**：Hark 设了一个每 10 分钟运行一次的定时任务（看门狗），每次：

1. 检查 VM 是否还在；
2. 把正在训练的实验的 `last.pt`、`log.csv` 下载到本地；训练完的实验下载 `best.pt`、`log.csv`、`curves.png`、`config.json`、`summary.json`；
3. 如果 VM 丢了：重新分配 VM → 上传代码、数据和已下载的 `runs/` → 重启队列。`train.py --resume` 会从 `last.pt` 接着训练（模型、优化器、学习率调度器、混合精度缩放器、当前轮数、最佳准确率、早停计数都会恢复）。

### 3.7 收尾

所有阶段结束后执行 `colab --auth oauth2 stop -s fer` 释放 VM，并用 `colab --auth oauth2 usage` 确认没有正在使用的 VM，避免继续扣费。

## 4. 各阶段做了什么

| 阶段 | 内容 | 用到的数据 |
|---|---|---|
| 1 | A0–A3 各训练 1 个种子（seed 0） | Training 训练，PublicTest 选最佳轮 |
| 2 | PublicTest 前两名 A1、A2 各补 seed 1、2，共 6 个模型 | 同上 |
| 3 | `python evaluate.py --runs ... --split PublicTest` 比较：最佳单模型 70.30%、A1×3 71.50%、A2×3 70.63%、A1+A2×6 71.52%，选最高的六模型集成，写入 `final_runs.txt` | PublicTest |
| 4 | `python evaluate.py`（默认读 `final_runs.txt`、评估 PrivateTest），只跑 1 次：73.11% | PrivateTest |
| 5 | 关闭 Colab，下载 `reports/`，写 README，打包 | — |
| 7 | A0、A3 补 seed 1、2，让 A0–A3 都有 3 个种子的均值 ± 标准差；不改最终模型，不再跑 PrivateTest | PublicTest |

每个模型训练结束时还会在 PublicTest 上比较“原图”和“原图 + 水平翻转取平均（TTA）”，后者更高就在 `summary.json` 里记 `use_tta: true`，评估和前端都按这个设置。

## 6. 每个模型的训练时长（Colab T4）

| 实验 | seed 0 | seed 1 | seed 2 |
|---|---|---|---|
| A0 无增强 | 37 轮 / 15 分钟 | 40 轮 / 17 分钟 | 52 轮 / 22 分钟 |
| A1 + 增强 | 70 轮 / 30 分钟 | 75 轮 / 33 分钟 | 97 轮 / 42 分钟 |
| A2 + 标签平滑 | 100 轮 / 44 分钟 | 87 轮 / 38 分钟 | 74 轮 / 33 分钟 |
| A3 + Dropout + Erasing | 100 轮 / 45 分钟 | 80 轮 / 36 分钟 | 100 轮 / 45 分钟 |

不足 100 轮的是触发了早停（PublicTest 连续 20 轮没有提升）。时长由 `log.csv` 的 `seconds` 列相加得到。

## 7. 自己复现的方法

结果有随机性（数据加载顺序、GPU 运算），重新训练会有约 ±0.5% 的差别，属于正常的种子波动。

### 7.1 在自己电脑上（有 NVIDIA 显卡）

```bat
scripts\setup_env.bat
.venv\Scripts\activate
python train.py --exp A1 --seed 0        :: 时间取决于显卡，T4 上约 30 分钟
python evaluate.py --runs runs/A1_s0 --split PublicTest
```

中断后加 `--resume` 继续。要复现全部 12 个模型，就把 `--exp` 换成 A0–A3、`--seed` 换成 0、1、2。

### 7.2 在 Colab 网页上（最简单）

1. 打开 colab.research.google.com，新建笔记本，“修改 → 笔记本设置”选 T4 GPU。
2. 左侧文件栏上传代码 zip 和 `data/icml_face_data.csv`（或 `fer2013.npz`）。
3. 依次运行：

```python
!unzip -q /content/fer_final.zip -d /content
%cd /content/project2
!mkdir -p data && mv /content/icml_face_data.csv data/
!pip install -q -r requirements.txt
!pytest -q tests
!python train.py --exp A1 --seed 0
!python evaluate.py --runs runs/A1_s0 --split PublicTest
```

4. 训练完下载 `runs/` 文件夹。网页标签页开着时 VM 不会像命令行那样很快被回收；如果断了，重新连上后加 `--resume` 继续即可（前提是 `runs/` 还在，必要时先保存到 Google Drive）。

### 7.3 规则（复现时也要遵守）

- 选模型、选 TTA、选集成方案只看 PublicTest。
- PrivateTest 只在方案完全确定后用 `evaluate.py` 跑一次，不能根据它回头调整。
